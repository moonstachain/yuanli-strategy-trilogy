## B. 学习契约

- 旧判断：文件交付、任务勾选或自动化跑完，就等于项目完成。
- 新判断：只有 Goal、Action、Evidence、Writeback、Mirror 闭合，行动才从一次性交付升级为系统资产。
- 学员动作：把一个真实任务改写为可交给人或 AI 执行并可验收、可回写的链路。
- 最终产物：OSA 行动链。
- 验收标准：
  1. 有明确目标与不做边界。
  2. 动作有负责人、输入、输出和完成条件。
  3. 有可复核证据，不只是一句“已完成”。
  4. 写明回写位置与下一次复用方式。
  5. Issue、看板、模块或日志等镜像状态一致。

## C. 小切口

### 场景

一个团队刚完成重要项目：页面上线、文档交付、客户也收到结果。三个月后再做类似任务，团队发现关键判断仍在创始人脑中，模板没有更新，案例找不到，上次踩过的坑再次出现。第一次“完成”了，第二次却仍从零开始。

- 具体时刻：新成员问“上次为什么这样做”，没人能给出证据和决策记录。
- 表面问题：知识库没有整理好。
- 真正两难：继续奖励快速交付，还是为证据、回写和镜像付出收口成本。
- 已付代价：重复沟通、重复犯错、状态假绿、系统失忆。
- 开场问题：如果下一次仍然从零开始，上一次真的完成了吗？
- 学员自检：你最近一个“完成”的任务，下一位接手者能否在十分钟内找到目标、证据与复用方法？

## D. 概念硬核

### 一句话定义

> 一条链路，是把战略地图中的判断，转化为可重复执行、可交给人或 AI、可验收、可回写、可自动化的行动流程。

### 它不是什么

- 不是待办事项。
- 不是临时任务。
- 不是自动化脚本堆砌。
- 不是只有输出、没有证据的交付。
- 不是任务跑完但系统没有变强的清单。

### 第一性问题

> 如何把战略判断变成可复用、可执行、可验收、可自动化、可回写的行动？

### 五个关键变量

1. Goal：为什么做、做到什么、什么不做。
2. Action：谁在什么输入上执行什么动作。
3. Evidence：什么可复核事实证明动作和结果发生。
4. Writeback：新判断、模板、案例或流程写回哪里。
5. Mirror：Issue、看板、模块、文档与执行状态是否一致。

### 核心机制

```text
战略判断
→ Goal 明确边界
→ Action 形成可执行步骤
→ Evidence 阻止口头假绿
→ Writeback 把结果变成下一次输入
→ Mirror 保持系统状态一致
→ 下一轮更快、更稳、更强
```

### 适用边界

- 极小的一次性动作可以简化，但高价值、可重复或多人协作任务必须闭环。
- 自动化不是必要条件；可重复、可验收、可回写才是。
- 证据不是原始日志堆积，而是足以支持验收的最小事实。
- C4 不替代 C3 的战略判断；错误方向被高效执行仍然是错误。

### 常见误用

- 把“有 SOP”误当成链路闭合。
- 用截图或长日志代替可读证据。
- 文档更新了，Issue 和看板仍显示旧状态。
- 只回写结果，不回写判断、失败原因和下次入口。

## E. 大纵深

### 纵深轴

组织进化纵深 + 企业生命周期纵深。

### 历史与结构节点

1. 手工作坊：经验依赖师傅个人。
2. 工业流程：标准化动作与质量控制。
3. 知识组织：决策依据、案例和反馈变得关键。
4. AI / Agent 协作：任务必须写成输入、输出、验收和权限边界。
5. 递归 OS：任务结果进一步更新文脉、大脑、地图、链路与 Skill。

### 四证规划

#### 理论证

- 证明：组织学习不仅需要行动，还需要反馈、纠偏与对规则本身的更新。
- 来源候选：Argyris 的单环 / 双环学习；Deming / PDSA；知识创造研究。
- 证据等级：primary。
- 状态：to_verify。

#### 数据证

- 证明：组织中“声称完成”与“具备证据、回写、镜像”的任务比例可能显著不同。
- 来源候选：从 Soul 的 Issue、backwrite-log 与 false-green 检查中建立内部基线。
- 证据等级：official_data（内部治理数据）。
- 状态：to_verify。

#### 案例证

- 证明：本次课程生产如果只写三节课，就是一次性交付；当标准、模板、Schema、Skill、Resolver、试跑与回写同时建立，下一次课程生产才获得可复用入口。
- 来源：本课程目录与 Soul 对应文件。
- 证据等级：single_case。

#### 反例证

- 证明：SOP 很完整但目标错误、证据缺失或状态不同步，仍会形成高效的假绿。
- 来源：Soul `yuanli-os-canon-template-governance` 的阶段绿 / 局部绿规则。
- 证据等级：single_case。
- 状态：verified（内部治理正典）。

### 证据结论

链路价值不在步骤数量，而在它是否把一次任务变成下一次可调用的判断、证据、模板和入口，并让系统知道真实状态。

## F. 高弧光

- 作者旧信念：把客户结果交付好、把文件做完，就已经尽到了责任。
- 信念被击穿：项目越多，系统却反复失忆；完成声明无法自动变成组织能力。
- 真实代价：收口需要额外时间，也会暴露之前被“完成”掩盖的缺口。
- 价值裁决：宁可承认 `completed_with_followup`，也不以漂亮的完成叙事制造假绿。
- 主动放弃：放弃“快速宣布完成”的即时满足。
- 人格金句：

  > 真正的完成，不是这次做完，而是下一次不再从零开始。

- 对学员提出的选择：你愿意为系统真实付出收口成本，还是继续奖励一次性交付？
- 作者确认状态：pending。

## G. 强落地

### 工具

《GAEWM 链路卡》

```text
Goal：目标、边界、验收
Action：动作、责任、输入、输出
Evidence：最小可复核证据
Writeback：写回文脉 / 大脑 / 地图 / 链路 / 模块 / 模板
Mirror：Issue / 看板 / 文件 / 状态同步
```

### 现场练习

1. 选择最近一个真实任务。
2. 用一句话写 Goal，并补一条“不做”。
3. 把 Action 写成可交给另一人或 AI 的输入 / 输出契约。
4. 删除原始日志，只保留最小验收证据。
5. 指定一个回写位置。
6. 检查至少两个镜像状态是否一致。

### 学员产物

一张完整 GAEWM 链路卡，能由另一人或 AI 按卡执行，并由第三人只看证据完成验收。

### 评分规则

- 0 分：只有待办或完成声明。
- 1 分：有动作与输出，没有证据或回写。
- 2 分：有证据与回写，但镜像或下一入口不清。
- 3 分：五段闭合，可执行、可验收、可复用。

### 七天迁移任务

让一位没有参与原任务的人仅凭链路卡复现或审计一次任务，记录他仍需追问的三个问题并回写模板。

### 失败信号

执行者仍必须依赖创始人口头补充关键判断，或验收者无法仅凭证据判断完成状态。

### 下一接口
