# 原力战略课程能力运行手册 v2

> 唯一入口：`yuanli-content-engineering` 读取同目录 `capability-router.yaml`。团队不需要直接记忆下游能力名。

## 1. 总控状态

- 当前可完成：从课程 brief 到授课卡、四证包、讲稿、PPT、工作簿、营销草稿、小鹅通交接包的本地 dry-run。
- 当前不可完成：真实课堂结果、真实时码金句、七天迁移结果、正式发布和 Soul 正典升级。
- 九项受管能力当前是 `callable + instruction_smoke_pass`；Governor `validation_state` 仍为 `unknown`。
- 三项降级债：脑面缺 CLI helper；课程/营销叙事缺声明 references；视频工厂缺 scripts 与 workflow references。

## 2. 每次运行的共同入口

1. 明确要处理的 `stage_id`。
2. 核对前一环 receipt 与 `input_contract`，文件存在不等于输入合格。
3. 调主能力；受限或失败时记录原因，再按 `fallbacks` 顺序降级。
4. 按 `output_contract` 交棒，运行 `quality_gate`。
5. 写无敏感 receipt 和 Evolution Note；所有外部写入保持 `false`，除非明哥对该动作单独授权。

## 3. 分环节运行卡

### 正典对齐

在唯一判断、概念定义、B4 口径或作者经历变化时调用。输入必须含课程边界和目标模块。先由内容工程读取 Soul；脑面 helper 缺失时直接回退仓内文件检索。输出按“已裁决 / 工作假设 / 外部参考 / 待验证”四层交棒。正典升级必须另开 Soul PR。

### 学员洞察

只在有受权访谈、逐字稿或匿名材料时抽取真实语言、两难与代价。没有材料时只能产出访谈提纲与 `evidence_gap`，不得写成真实小切口。任何可识别学员信息不入仓。

### 研究设计

在任何联网搜索前调用。输入必须有“要支持什么决策”。输出至少包含研究问题、证据标准、停止条件与效度威胁。主能力不可用时写三行 spec：决策、需要的证据、何时停止。

### 大纵深

输入为 research spec 与正典包。依次使用研究编排、横纵研究、全网语义搜索和网页回读。每个关键结论要求至少三源交叉；没有回读原文的来源标记 `candidate/to_verify`。搜索额度耗尽不是编造依据。

### 原力叙事与强落地

先写概念硬核，再进入心智隔离、小切口、大纵深、新植入、高弧光。真实学员材料为空时使用“情境练习”并清楚标注非真实人物。高弧光作者经历保持 `pending`。唯一工具只生成《原力战略起点卡 v2》。

### 内容质检

检查 Schema、来源、AI 套话、作者经历和状态词。事实没有来源即删除、改写为问题或降级为候选。质检 `pass` 不提升真实课堂状态。

### PPT / DOCX / XLSX

只接受通过的授课卡与讲稿。PPT 不超过 24 页，使用 Greenbook Luxury；DOCX 采用紧凑参考手册；XLSX 由公式计算评分与汇总。三类资产必须先渲染、逐页或逐表检查，再写资产 receipt。

### 真实试讲

每班 8–12 位真实学员。明哥确认排期、录制与隐私告知后才可进入。没有真实 attendance、授权与录像 receipt，状态保持 `live_trial_pending`。两班分别验收，不以合并样本掩盖某班失败。

### 转写复盘

只处理受权录像。输出带时码逐字稿、误解、用户语言、弧光反应和节奏断点。金句必须逐字回读；仓库只保留匿名汇总与原始材料的受控指针。

### 七天迁移

学员自愿后才在飞书创建跟踪项。目标：80% 能用两条事实说明主卡点，70% 起点卡达 8/10，50% 七天回传有效行动证据。提醒消息、表格写入和任务创建均需单独授权；本轮只交付字段与离线模板。

### 营销研究与转译

只从已批准课程正典、已核验外部证据和真实课堂授权证据派生。首发前只生成公众号母内容、三条视频号脚本、三组朋友圈、详情页与 FAQ。流量对标只是表达参考，不能替代课程价值。

### 现场再生产

必须有真实录像、真实时码和传播授权。视频工厂缺脚本，故当前强制降级到短视频发布包与人工剪辑交接。试讲前 publish pack 只能是“无真实时码的结构样例”。

### 小鹅通草稿

默认只生成本地创建包。若明哥另行授权平台写入，只允许创建未发布草稿并逐项核对课程名、课节数、顺序与视频。发布、定价、分享、通知、支付和删除分别确认，任何一个确认不自动授权其他动作。

### 正典回写

两班真实试讲和七天迁移完成后，先形成匿名汇总与 Evolution Note。方法变化可以提 Soul PR；真实正典裁决必须由明哥确认并走单独 PR。营销数据不能直接升级正典。

## 4. Receipt 与 Evolution Note

每个 receipt 写明调用身份、版本、内容哈希、输入输出、降级原因、检查结果、外部写入和下一闸门。只保存无敏感信息。Evolution Note 回答：这次哪项课程判断被证据改变、哪项能力有效或失效、下次从哪里复用。

## 5. 明哥需要确认的最小清单

1. 可公开的作者经历与高弧光表达。
2. 两班名单、排期、录制授权和隐私告知。
3. 外部平台的每一项写入。
4. 课程定价与正式发布。
5. 真实课堂证据是否申请进入 Soul 正典。

## 6. 禁止自动执行

- 编造学员语言、课堂数据、作者经历、引用、金句或时码。
- 自动录制、发消息、建任务、发布、定价、分享、通知、支付或删除。
- 把 dry-run、smoke、草稿、发布包合并描述成“已上架”。
- 把九项受管能力描述为 Governor `passed_current`。
- 在两班真实试讲前生产其余九课。
