## 录制前导演裁决

这个故事**不讲“Model 299 坠毁后立刻发明了飞行 checklist”**，因为当前证据包没有冻结这条常见传奇链。

只打穿一个更扎实的判断：

> **系统越复杂，越不能把关键安全条件只留在最优秀的人脑子里。**

# 05:30—07:10｜深｜三个镜头解释“为什么人脑不是可靠的唯一控制面”

[DEEP_DIVE]

讲师：

> 第一，人因工程。
>
> 人的工作记忆有限，尤其在时间压力、环境变化、多任务并发时，遗漏不是道德问题，而是系统风险。
>
> 第二，可靠性工程。
>
> 一个关键条件如果只能靠“某个高手记得”，它就是一个单点故障。
>
> 第三，组织设计。
>
> 真正成熟的组织不会只问：
>
> “谁犯错了？”
>
> 它还会问：
>
> **为什么这个错误可以一路走到现实里，直到造成后果才被看见？**

[SCREEN]

```text
关键判断
只在人脑里
↓
不可见
不可检查
不可继承
↓
单点故障
```

# 08:15—09:10｜名｜OS 第一次被定义成“判断继承”

[CONCEPT_REVEAL]

[SCREEN]

> # **原力 OS = 让关键判断不再只存在本人脑中。**

讲师：

> C1 留下什么不能变。
>
> C2 留下我们凭什么相信。
>
> C3 留下现在押什么、何时停止。
>
> C4 留下谁做、怎样进入现实、结果如何回写。

> 所以 OS 不是文件更多。
>
> 不是 Agent 更多。
>
> **它首先是把关键状态、关键判断、关键边界，从“希望人记得”，变成“系统看得见”。**

## FACT / INTERPRET 边界

### FACT

- Model 299 于 1935-10-30 在 Wright Field 测试飞行中坠毁。
- 官方事故调查摘要指出，事故不是结构、发动机、控制面或自动驾驶故障。
- 关键原因是方向舵和升降舵表面控制处于锁定状态，使飞行员无法控制飞机。

### INTERPRET

- “复杂性债务”“系统替人承担记忆责任”“单点故障”属于课程解释。

### 禁讲

- “事故后 Boeing 立即发明现代 checklist”作为已冻结事实。
- “飞行员因为粗心导致事故”作为简单归因。
