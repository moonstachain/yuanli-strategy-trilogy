# 通识课 2.0 · 证据与案例计划

## 一、目的

本文件不负责“给原力战略找背书”，而负责保证课程中的外部事实、案例、数字和因果叙述可追溯、可核验、可降级。

## 二、证据状态

统一使用：

```yaml
source_status:
  - to_verify
  - verified_primary
  - verified_secondary
  - internal_case_material
  - human_confirmed
  - disputed
  - excluded
```

原则：

- `to_verify` 不得作为正式结论口播；
- 内部案例材料不得自动写成已审计商业事实；
- 作者本人经历必须 Human Confirm；
- 正典定义以 Soul 为准，不以外部论文反向改写；
- 课程案例只负责帮助理解，不自动证明因果。

## 三、三类案例结构

### 1. 时代命运案例｜解释“秘密如何出现”

目标：让学员看到新旧生产函数交替时，旧世界可能仍然非常成功，而新财富窗口已经出现。

候选：

- Nokia / iPhone：旧生产函数做到极致时，新生产函数开始替换；
- 任天堂 Wii：不在旧性能战里更强，而是重定义谁有资格成为玩家；
- Ford：新范式创新如何进一步被压成极致性价比。

进入正式讲稿前要求：

- 时间线核验；
- 关键数字使用一手或高质量来源；
- 明确“原力解释层”不是企业官方自述。

### 2. 人物临界案例｜解释“为什么偏偏是这个人看见”

目标：不写伟人传记，只写一个结果未知、代价真实的命运临界点。

候选：

- 塞麦尔维斯；
- 约翰·斯诺；
- 弗朗西丝·凯尔西；
- 屠呦呦。

必须回答：

- 他看见了什么异常？
- 当时主流解释是什么？
- 为什么另一条道路也合理？
- 他支付了什么代价？
- 最终留下了什么可被后人调用的公共遗产？

### 3. 真实学员 / 客户案例｜解释“这与我有什么关系”

优先使用已有案例库：

- 苹果妈妈；
- 水月老师；
- 韬哥；
- 卷卷；
- 张姐 / 达哥；
- 帆哥；
- Matthew。

使用纪律：

- 区分原始逐字稿、综合材料、经营数据、真实 Outcome；
- 对证据不足处使用“现有案例材料显示 / 候选解释”；
- 不把 derived / unilateral synthesis 冒充本人确认；
- 不因单次付款或赞美宣称 Force Asset = compounding。

## 四、每一幕的最低证据需求

### 序幕｜AI重新定价

至少需要：

- 一个 AI 降低标准化知识 / 内容 / 执行成本的可靠事实；
- 一个说明判断、问题定义或差异生成仍需更高阶选择的案例或实验；
- 避免使用“80%工作必然被替代”等未经核验的绝对数字。

### 第一幕｜秘密 × 一万倍

至少需要：

- 一个时代裂缝案例；
- 一个品类 / 认知重构案例；
- 一个从创始人单点走向多节点复制案例；
- 一个四壁垒中至少两类控制权可观察的案例。

### 第二幕｜原力母体

不需要宣称脑中存在“母体器官”。

需要：

- 跨时期证据；
- 替代解释；
- 反证；
- 选择预测或真实行动证据。

### 第三幕｜原力 OS

需要：

- 至少一个“知识存在但没有进入行动”的失败案例；
- 至少一个“Outcome / Learning 被下一任务明确复用”的闭环案例；
- 不以系统上线、Agent运行或文档存在替代复利证明。

## 五、事实与解释分层

正式课程材料建议统一标记：

```text
FACT        已核验事实
INTERPRET   原力战略解释
HYPOTHESIS  待现实验证的假设
CANON       Soul冻结正典
```

任何案例都不得把 `INTERPRET` 写成企业或人物的 `FACT`。
